# 狼人杀 · H5 在线游戏

一个**服务端权威**的 6-18 人在线狼人杀。默认板子是标准「预女猎白」，并已支持
混血儿、通灵师、机械狼、舞者、假面、白狼王与守卫等可选角色。

玩法流程按需求实现：**狼人先定刀 → 女巫决定救 / 毒 → 预言家查验 → 天亮公布平安夜或死讯 → 第一天警长竞选 → 白天发言 → 投票放逐**，
一直循环到狼人全灭（好人胜）或神职全灭 / 平民全灭（狼人胜，即「屠边」）。

---

## 一、怎么跑起来

只需要两步。**不需要另装数据库，不需要编译前端，不需要任何云服务。**
服务端会使用 Node 内置 SQLite，并自动创建 `data/werewolf.db` 保存账号和战绩。

```powershell
npm install          # 第一次运行需要（只需一次）
npm start
```

启动后终端会打印两个地址：

```
本机访问    http://localhost:5180
局域网访问  http://192.168.x.x:5180   ← 手机连同一个 WiFi 就能打开
```

用电脑浏览器打开「本机访问」就能自己先看界面。

## 二、怎么和 12 个朋友一起测

### 方式 A：局域网（最快，零成本）

1. **先跑一次环境自检**：

   ```powershell
   npm run doctor
   ```

   它会检查服务端是否在跑、局域网地址是否可达、以及**Windows 防火墙会不会拦掉手机的连接**，
   并在有问题时直接给出可以在管理员 PowerShell 里执行的修复命令。

   这一步很重要：**服务端自己电脑能打开，不等于手机能连上**。
   防火墙拦掉入站连接时浏览器只会一直转圈，不给任何原因 —— 先自检能省掉一晚上的折腾。

2. 让 12 个人连上**同一个 WiFi**（和跑服务端的那台电脑同一个网络）。
3. 把终端里打印的「局域网访问」地址（形如 `http://192.168.2.67:5180`）发给其他玩家。
4. 每个人用手机浏览器打开链接 → 注册账号。新账号初始密码是 `1`，首次进入前会强制修改。
5. 一个人点「创建房间」→ 把页面上显示的 **6 位房间号**发给其他玩家。
6. 其余玩家可以从公开大厅直接加入，也可以输入房间号加入。
7. 12 人齐了以后，房主点「开始游戏（发牌）」。

> 也可以直接让朋友点你生成的**邀请链接**（房间页有「复制邀请链接」按钮），
> 链接里带了房间号，点开就是加入页面，不用手输。

**手机还是打不开？按这个顺序排查：**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一直转圈 / 无法访问此网站 | Windows 防火墙拦了入站 | 按 `npm run doctor` 给出的命令放行（需管理员） |
| 电脑能开，手机不能 | 手机和电脑不在同一个网段 | 注意别一个连 5G 一个连 2.4G 的不同 SSID |
| 所有设备都连不上 | 路由器开了「AP 隔离 / 客户端隔离」 | 进路由器设置关掉 |
| 时好时坏 | 电脑上有 VPN / 代理软件在改路由表 | 临时关掉 VPN 再试 |

### 方式 B：手机不在同一个 WiFi（需要公网部署）

局域网方式只适合同一个 WiFi。想让不在身边的朋友也能玩，**必须把服务端部署到有公网地址的机器上** ——
这是实时对战游戏（WebSocket 长连接），不能像普通网页那样丢到静态托管，必须有一个一直跑着的进程。

三种方案、完整的服务器命令、HTTPS 配置、以及**部署后怎么验证**，
都在 **[`docs/部署指南.md`](docs/部署指南.md)**。要点：

| | 多久能用 | 要备案吗 | 适合什么阶段 |
|---|---|---|---|
| 内网穿透（免费，跑在自己电脑上） | 几十分钟 | 不用 | 临时试玩 |
| **香港/境外服务器** | 1～2 天 | 不用 | H5 快速上线 |
| **国内服务器 + ICP 备案** | 2～4 周 | 必须 | 面向大陆用户长期运营 |

> 只做 H5 时不必为了小程序购买资源。先小范围测试可用内网穿透；准备长期运营时，
> 再根据玩家地区、延迟和备案要求选择服务器。

部署完**务必**先自检再发给朋友：

```powershell
npm run doctor -- --url https://你的域名
```

它会真正发起一次 WebSocket 握手 —— 这一步能抓出「网页能打开但进房间连不上」这个
最常见的部署故障（反向代理漏配 Upgrade 头），而这个故障在浏览器里没有任何报错。

### 方式 C：一个人先试（机器人填房）

想先自己确认流程没问题，不需要凑 12 个人：

```powershell
# 1) 先在浏览器里创建房间，记下 6 位房间号，比如 AB3D7K
# 2) 另开一个终端：
npm run bots -- AB3D7K        # 默认塞 11 个机器人，凑满 12 人
# 3) 回到浏览器点「开始游戏」，机器人会自动出牌
```

机器人会自己刀人、验人、投票，你可以一直玩到分出胜负，用来验证界面和流程。

## 二·五、添加到手机主屏幕

朋友第一次打开链接后，可以把它添加到主屏幕，之后就是一个**图标 + 全屏、没有地址栏**的入口，
用起来像一个独立的手机应用：

- **iPhone**：用 Safari 打开 → 底部「分享」按钮 → 「添加到主屏幕」
- **安卓**：用 Chrome 打开 → 右上角菜单 → 「添加到主屏幕」/「安装应用」

> 前提是**必须用 HTTPS**（http 下浏览器不给装）。图标已经做好了（`web/icon-*.png`），
> 需要重新生成时执行 `npm run icons`。
>
> 说明：iOS 用 Safari 添加即可；安卓 Chrome 如果没有自动弹出安装提示，
> 用菜单里的「添加到主屏幕」一样能得到图标。
> （要做到所有安卓机型都弹安装提示，还需要加一个 Service Worker；本项目刻意没加，
> 因为缓存会让更新后的代码不生效，对还在迭代的项目是更大的麻烦。）

## 三、账号、大厅与数据

- 用户名最多 12 个字符，忽略英文字母大小写，不能重复注册。
- 按需求，新账号初始密码固定为 `1`；因为这是公开弱密码，系统会在首次进入大厅前强制修改。
- 密码使用随机盐和 `scrypt` 哈希保存，不会把明文密码写入数据库。
- 登录会话默认保存 30 天；登录和注册接口有基础频率限制。
- 大厅只显示尚未开局且仍有空位的公开房间，每 5 秒自动刷新。
- 同一个大厅可以连续发起第 1、2、3…场；每场结束后回到原大厅，保留原座位。
- 已结束的场次会记录版型、座位、身份、阵营、胜负和结束时间，并累计每人的胜负与狼人 / 神 / 平民次数。
- 普通玩家只能看胜负和身份次数；厅主额外看到积分、排名和每场得分，并且只有厅主能删除场次。
- 积分规则：狼人胜 3 分、好人胜 1.5 分、狼人负 0.5 分、好人负 0 分；第一夜锁定的悍跳位在狼队获胜时再加 1 分。
- 「重新发牌」会彻底丢弃当前牌局并保持原场次编号；「结束并回大厅」会保存为提前结束，但不计胜负、身份次数和积分。
- 账号与战绩保存在 SQLite；**正在进行的房间仍只在内存里，服务端重启会丢失未结束对局。**

公网使用时必须放在 HTTPS/WSS 反向代理后面，否则密码和会话令牌会以明文网络流量传输。

### 为什么前端没有构建步骤？

`src/server/index.ts` 用 Node 24 内置的**类型擦除**（`module.stripTypeScriptTypes`）把
`web/app/*.ts` 实时转成浏览器能跑的 JS。好处：

- 改完代码**刷新浏览器就生效**，没有编译等待
- 部署只要 `npm start`，不依赖打包器
- 前端仍然是 TypeScript，`npm run typecheck` 会检查

代价：只能用「可擦除」的 TypeScript 语法。为此两个 tsconfig 都开了
`erasableSyntaxOnly`，`enum` / `namespace` / 构造函数参数属性 这类写法会在类型检查阶段直接报错，
而不是等到运行时炸。

## 五、已实现的规则

**版型由房主自己配。** 进房间后房主先定人数（6-18 人），再挑角色：
狼人和平民可以调数量，其余角色（预言家 / 通灵师 / 女巫 / 猎人 / 白痴 / 守卫 / 舞者 / 混血儿 / 白狼王 / 机械狼 / 假面）勾选。
**角色总数必须刚好等于人数**，否则开局按钮锁死并提示还差几个（服务端判定，客户端只负责显示）。
内置 9 套预设可一键套用，其中包含「12人假面舞会」「13人预女猎白混」与「12人机械狼通灵师」。

| 环节 | 规则 |
|---|---|
| 发牌 | 服务端洗牌，客户端只拿到**自己该看到的**信息 |
| 开局条件 | 版型自洽 + 座位坐满 + **除房主外所有人都点了「我准备好了」** |
| 夜晚顺序 | 普通旧板保持狼人 → 守卫 → 女巫 → 预言家；机械狼板为机械狼 → 守卫 → 狼人 → 女巫 → 通灵师；假面舞会首夜不含舞者/假面，第二夜起为舞者 → 假面 → 狼人 → 女巫 → 预言家 |
| 狼人 | 各狼独立点刀，**多数票**生效；平票或多数选「空刀」则平安夜；狼队实时看到彼此的选择 |
| 白狼王 | 属于狼人阵营，夜里和狼一起刀人；**白天可以自爆并带走一名玩家**，自爆后直接进入黑夜（当天不再投票） |
| 机械狼 | 初始不与普通狼人互认；首夜学习一人的具体身份，技能从下一夜生效；学狼人后加入狼刀，学白狼王不复制自爆，学女巫只复制一瓶毒药 |
| 混血儿 | 属于民边，首夜选择榜样但不知道其身份；预言家始终验为好人；个人胜负与积分跟随榜样阵营，身份次数仍计为平民 |
| 舞者 | 属于神职；第二夜起选择三名本局未进过舞池的存活玩家；2 比 1 时少数阵营出局；舞者自入池时三人免疫当夜狼刀；免疫毒药但仍消耗毒药 |
| 假面 | 属于狼营、预言家验为狼；不与普通狼互认；第二夜起先查一人是否在舞池，再给一人戴面具；面具只反转舞池结算阵营；普通狼全灭后继承刀权；免疫毒药 |
| 守卫 | 每晚守护一人免疫狼刀；**不能连续两晚守同一人**；**同守同救时该玩家依然死亡**；守护挡不住女巫的毒药 |
| 女巫 | 解药 / 毒药各 1 瓶，全局仅一次；**同一夜不能双药**；默认**不可自救**（可在房间配置里开） |
| 预言家 | 每晚验一人，得到「好人 / 狼人」，验人记录自己随时可查 |
| 通灵师 | 每晚查验一名玩家的**具体身份**，用于机械狼通灵师等特殊板 |
| 猎人 | 被狼刀死 或 被投票放逐 → 可开枪；**被女巫毒死、被白狼王带走 → 不能开枪** |
| 白痴 | 被投票放逐时翻牌免死，**永久失去投票权**，且不再成为投票目标 |
| 警长竞选 | 仅第一天：上警/不上警 → 随机警上发言顺序 → 可退水 → 警下投票；首轮平票进入 PK，重新投票仍平票则警徽流失 |
| 警徽 | 警长公开显示；决定白天发言方向并最后归票；放逐票为 **1.5 票**；出局后可移交给存活玩家或撕毁 |
| 投票 | 得票最多者放逐；警长票按 1.5 票；**平票或全员弃票 → 无人出局** |
| 胜负 | 屠边：狼人全灭 → 好人胜；**原本存在的**那一类（神职 / 平民）全灭 → 狼人胜 |
| 安全阀 | 超过 20 天仍未分胜负 → 流局（保证对局一定会在有限步内结束） |

> 「原本存在的」那一类很重要：如果版型里根本没配平民，就不能因为「平民数 = 0」在第一天判狼人胜。

### 语音播报（手机当法官）

打开后手机会念出「天黑请闭眼」「狼人请睁眼，请确认战术」这类流程指令，
不需要真人当法官，也不需要麦克风和录音权限（用的是浏览器内置的语音合成）。

- **房主默认开启，其他玩家默认关闭** —— 12 台手机同时念会互相干扰，想听就自己打开
- **天黑期间谁都改不了这个开关**（防止有人夜里临时开语音搞场外因素），大厅和白天才能改
- 台词由服务端生成，**只包含公开信息**：女巫阶段只念「女巫请睁眼」，绝不会把刀口念出来。
  这条有单元测试兜底 —— **同一阶段所有人的台词必须一模一样**，一旦有人拿到不一样的台词就说明掺进了隐藏信息
- **睁眼和闭眼都会念全**（「狼人请闭眼。守卫请睁眼，请选择今晚要守护的玩家。」）。
  不能因为某个角色死了就把那句省略掉 —— 省略本身就等于公布了死讯

### 夜间时长：时间不能携带任何信息 ★

这是本项目的核心公平性设计，**每个夜间角色阶段每晚都固定走完**，不管那个角色是死是活、有没有药：

| 角色 | 时长 | 为什么是这个数 |
|---|---|---|
| 狼人 | **90 秒** | 真的需要时间商量刀谁、谁去悍跳、怎么发言 |
| 女巫 | 40 秒 | 要看刀口、决定用不用药 |
| 守卫 | 30 秒 | |
| 预言家 | 30 秒 | |
| 混血儿 | 30 秒 | 仅第一夜选择榜样 |
| 机械狼 | 40 秒 | 每夜固定保留；只有首次可学习 |
| 通灵师 | 30 秒 | 查验具体身份 |
| 舞者 | 60 秒 | 选择三人并考虑舞池阵营组合 |
| 假面 | 60 秒 | 同一回合完成查舞池与戴面具两步 |
| 天黑过渡 | 5 秒 | |
| 天亮结算 | 2.5 秒 | |

**一个完整夜晚 ≈ 3 分 18 秒**（五神全开，实测 197.5 秒；跑 `npm run pace` 得到的，不是算的）。

版型不同这个数会变 —— 「预女猎白」没有守卫，少 30 秒 ≈ 2 分 48 秒。
所以约 12 个人开局前，先照着自己的版型跑一次 `npm run pace`，心里有个数。

- 最后 5 秒界面显示大号数字 + 语音念 5、4、3、2、1 —— **倒数是提醒，不是终止信号**
- 只有房主可以按「跳过阶段」提前收工；未完成行动会按规则自动处理，并写入公开日志
- **绝不允许**因为「女巫没药了」就跳过女巫阶段 —— 否则全场从阶段时长就能推出
  「女巫空手了」，后面几晚狼队就可以毫无顾忌地刀她。这是玩家实测发现的问题，已修

### 实测节奏（`npm run pace`）

配的秒数和真人实际感受到的秒数**可能不是一回事** —— 定时器写错、阶段被提前推进、
倒数不生效，这些从代码上看不出来。所以有一个专门的实测脚本：

```powershell
npm start            # 终端 A：服务端要在跑
npm run pace         # 终端 B：自己建房、自己就绪、跑完一夜，打一张对照表
```

它用机器人跑一局，在每次阶段切换的瞬间打时间戳，输出「配置 vs 实测 vs 误差」，
并检查四个夜间阶段是不是都出现了 5、4、3、2、1 的倒数。改完 `PHASE_TIMEOUT_MS` 跑一次就知道有没有到位。

```
  阶段                          配置      实测      误差
  第1天 NIGHT_START                   5.0s      5.0s     +0.0s
  第1天 NIGHT_WOLVES                 90.0s     90.0s     +0.0s
  第1天 NIGHT_GUARD                  30.0s     30.0s     +0.0s
  第1天 NIGHT_WITCH                  40.0s     40.0s     +0.0s
  第1天 NIGHT_SEER                   30.0s     30.0s     +0.0s
  第1天 NIGHT_RESOLVE                 2.5s      2.5s     +0.0s

  最后 5 秒倒数：
    1:NIGHT_WOLVES  → 5 4 3 2 1
    1:NIGHT_GUARD   → 5 4 3 2 1
    1:NIGHT_WITCH   → 5 4 3 2 1
    1:NIGHT_SEER    → 5 4 3 2 1
```

> 默认用「五神全开」版型，因为「预女猎白」里**没有守卫**，测不到 `NIGHT_GUARD` ——
> 而守卫阶段恰好是最需要盯着的那个（它以前会被错误跳过）。
> 换版型：`npm run pace -- 12 12-classic-white-idiot`

### 音效

警长当选时放「金色传说」—— 这是真实录音不是 TTS，TTS 念不出那个味儿。
文件在 `web/sounds/golden-legend.mp3`，由服务端直接托管（`.mp3` 已在 MIME 表里）。

警长当选或警徽移交成功时会自动播放；大厅的语音面板仍保留**「▶ 试听金色传说」**按钮，
开局前可以先确认手机能正常出声。

> 移动端自动播放限制：iOS / 微信要求先有用户手势才能出声。所以按钮会先「解锁」
> 再播放；开语音开关那一下也算一次手势。

**还没有做的**（后续可加）：文字聊天、真人语音、中途换人、进行中房间持久化。

## 六、怎么验证它是对的

```powershell
npm test            # 119 个测试：94 规则 + 8 账号大厅战绩 + 15 防火墙 + 2 重连
npm run typecheck   # 服务端 + 前端类型检查
npm run doctor      # 本机环境自检（服务端 / 局域网 / 防火墙）
npm run doctor -- --url https://你的域名   # 线上部署自检（含真实 WebSocket 握手）
npm run smoke:auth   # 服务运行时：账号鉴权 + 公开大厅集成测试

# 端到端：12 个真实 WebSocket 客户端跑完一整局
$env:WEREWOLF_TIMEOUT_SCALE='0.02'   # 把过场时间压到几十毫秒，否则一局要跑几分钟
npm start                             # 终端 A
npm run smoke                         # 终端 B
```

> `npm run smoke` 需要服务端已经在跑（它会连 `ws://127.0.0.1:5180/ws`），
> 所以两个终端各跑一条命令。

单元测试和冒烟测试覆盖的重点是**一旦写错就会毁掉整局游戏**的地方：

- 女巫双药、自救、解药复用等边界
- 猎人开枪条件（被毒死不能开枪）
- 白痴翻牌后的投票权
- 投票平票 / 全员弃票
- 屠边胜负的所有分支
- **信息隔离**：好人客户端里绝不能出现 `"WOLF"` 这个字符串
  （这条是真在浏览器里跑出来的——它先后抓出了「日志泄露女巫用药」「死因提前下发」
  「胜负结果提前下发」三个真实漏洞）
- **夜间阶段不被跳过**：女巫空手 / 守卫出局 / 预言家出局时，阶段都必须照常出现
  （跳过 = 用时长泄露隐藏信息）
- **上帝视角权限**：活着的玩家即使伪造 `game.godView` 请求也拿不到 `revealAll`
- **状态机终止性**：全员挂机也必须能在有限步内收场
- **防火墙判定**：用真实抓取的 netsh 输出做测试，特别保证不会**误报**「能连上」
  （误报会让用户以为今晚能测，结果手机连不上）

## 七、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `WEREWOLF_PORT` | `5180` | 服务端口。**特意不读 `PORT`**，因为很多环境会把 `PORT` 预留给别的用途 |
| `WEREWOLF_HOST` | `0.0.0.0` | 监听地址。只想本机访问就设 `127.0.0.1` |
| `WEREWOLF_TIMEOUT_SCALE` | `1` | 阶段时长倍率。`0.05` = 快速模式，用于测试和演示 |
| `WEREWOLF_DB_PATH` | `data/werewolf.db` | SQLite 数据库位置；自动化测试可设为 `:memory:` |

调试手机端问题时，在链接后面加 `?debug=1`，就能在页面控制台用 `window.__werewolf` 查看客户端状态
（手机上没法开开发者工具，这个很有用）。
