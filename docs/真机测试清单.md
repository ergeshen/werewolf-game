> 这份是给**现场用的**。目标不是"把功能都点一遍"，而是回答三个**只有真机能回答**的问题。
> 功能有没有 bug，自动化测试已经覆盖了 119 条；现场时间要花在测试覆盖不到的地方。

## 零、测试前 5 分钟（只有你一个人做）

```powershell
# 1) 起服务端（这个终端要一直开着，别关）
npm start
```

> **重要**：请你自己在这个终端里跑 `npm start`，不要用我起在后台的那个 ——
> 后台那个会话一结束就没了。你自己的终端你能看见报错、能随时 Ctrl+C。

启动后会打印局域网地址，记下来，比如：

```
局域网访问  http://192.168.31.50:5180   ← 手机连同一个 WiFi 就能打开
```

```powershell
# 2) 另开一个终端，自检防火墙（手机打不开 90% 是这里）
npm run doctor
```

**⚠️ 三个必须知道的坑：**

| 坑 | 说明 |
|---|---|
| **服务端一关，进行中的房间会消失** | 账号和已完成战绩会保留，但房间号、座位和未结束对局仍在内存里。**中途别重启服务端。** |
| **电脑不能休眠** | 休眠 = 服务端停 = 全场掉线。记得把电源计划调成"从不休眠" |
| **正式测试前先确认环境变量** | 正式局不要设置快速测试用的 `WEREWOLF_TIMEOUT_SCALE=0.02`，否则阶段会快到无法正常游玩 |

一个大厅号可以连续玩多场。12 个人都进同一个大厅号；每场结束后返回原大厅，由厅主发起下一场。重启服务端后仍需重新创建大厅并把新大厅号发到群里。

## 一、先自己跑一遍（强烈建议，5 分钟）

在喊人之前，先确认整条链路是通的 —— 不然 12 个人等着你排错会很尴尬。

```powershell
# 先自己用浏览器开一个房间，记下 6 位房间号
npm run bots -- <房间号> 11
```

机器人会自动入座 + 点就绪。回到浏览器点「开始游戏」，整局会自己往前跑。

**还要顺手确认这两件事：**

1. **点一下大厅里的「▶ 试听金色传说」** —— 确认你这台手机出得了声。
   顺便让每个人开局前都点一下（移动端不先点一次，后面的语音播报很可能全程没声）。
2. **跑一次 `npm run pace` 看夜间时长对不对**（另开一个终端，约 5 分钟）：

```powershell
npm run pace         # 自己建房、自己就绪、跑完一夜，打一张「配置 vs 实测」对照表
```

关机前我实测过是 **197.5 秒 ≈ 3 分 18 秒一夜**，四个夜间阶段都走满、倒数都是 5 4 3 2 1。
你自己再跑一次确认，顺便看看换成你要用的版型之后是多少。

想快点跑完流程就加一行环境变量把时长压扁（**正式测试时不要加**）：

```powershell
$env:WEREWOLF_TIMEOUT_SCALE='0.2'   # 所有阶段时长 × 0.2
npm start
```

## 二、12 个人到场后的流程

| 步骤 | 谁做 | 看什么 |
|---|---|---|
| 1 | 每个人 | 浏览器打开链接 → 注册/登录；新账号用初始密码 `1`，然后按提示修改密码 |
| 2 | 房主 | 先定**人数**（12），再挑角色 —— 总数必须刚好等于人数，否则「开始游戏」按钮点不了，界面会告诉你差几个 |
| 3 | 非房主 11 人 | 点「我准备好了」。房主能看到谁还没点 |
| 4 | 房主 | 点「开始游戏（发牌）」 |
| 5 | 每个人 | 确认**只有自己看到自己的身份**，狼能看到另外 3 个狼队友 |
| 6 | 狼队 | 第一夜确定**悍跳位**：全队只能有一个，锁定后不能改；狼队获胜时该玩家额外加 1 分 |
| 7 | — | 夜晚 → 白天 → 循环，直到分出胜负 |
| 8 | 出局的人 | 点「上帝视角」（会先弹确认框）。**还活着的人不该看到这个按钮** |
| 9 | 厅主 | 结束后点「保存结果并返回大厅」，确认大厅出现第 1 场记录，并显示胜负与身份次数 |
| 10 | 厅主 | 确认只有自己能看积分、排名和「删除」按钮；普通玩家看不到这些数据 |
| 11 | 厅主 | 发起第 2 场，确认场次编号递增；另测一次「重新发牌」仍保持原场次编号 |

### 多场大厅专项检查

1. 正常完成第 1 场：大厅应显示每人的胜负、狼人 / 神 / 平民次数；厅主另见积分和排名。
2. 第 2 场中点「结束并回大厅」：应保存“提前结束”回顾，但累计胜负、身份次数和积分不能变化。
3. 新开一场后点「重新发牌」：旧身份不能进入回顾，重新发牌后仍是同一个场次编号。
4. 厅主删除一场：所有玩家页面中的该场都应消失，累计数据与排名立即重算；普通玩家没有删除权限。
5. 白天让当前房主断网超过 60 秒：操作权应临时交给随机在线且存活的玩家；原房主回来后自动收回。夜间不移交。

## 三、★ 三个只有真机能回答的问题

这三个问题的答案会**反过来改设计**，所以请认真测、记下数字。

### 问题 1：狼人 90 秒，够不够？

**为什么重要**：现在配的是狼人 90 秒 / 女巫 40 秒 / 守卫 30 秒 / 预言家 30 秒。
90 秒是我按"要商量刀谁、谁去悍跳、怎么发言"估的，**没有真人实测依据**。

**已知的硬数据**（机器实测，已经替你确认过，不用再测）：

```
一个完整夜晚（天黑 → 天亮）= 197.5 秒 ≈ 3 分 18 秒
  天黑过渡 5s → 狼人 90s → 守卫 30s → 女巫 40s → 预言家 30s → 天亮结算 2.5s
最后 5 秒四个阶段都正常倒数（5 4 3 2 1）
```

**所以 12 个人要有个心理准备：一夜接近 3 分半钟**（加上白天公布 + 投票更长）。
如果实测下来大家觉得熬不住，把数字调小就行 —— 但**必须四个阶段一起调**，
只调狼人不会破坏公平性，只调某一个角色的阶段就会（时间又变成信息了）。

**怎么测**：第一夜，狼队里随便一个人拿手机开秒表（或者看界面上的剩余秒数）。

- 太紧（话没说完就被打断）→ 我们把 90 秒调大
- 太松（三个人干等 40 秒）→ 调小

**顺便观察**：房主是否频繁使用「跳过阶段」。这个按钮只有房主可见，点击后必须二次确认。

### 假面舞会专项（建议先开快速模式单独测一局）

1. 套用「12人 · 假面舞会」预设；第一夜应直接进入狼人阶段，不能出现舞者或假面操作。
2. 第二夜应依次出现舞者 60 秒、假面 60 秒、狼人 90 秒。
3. 舞者必须恰好选三人；已经进过舞池的人，后续夜晚不能再次选择。
4. 假面先查一人是否在舞池，页面显示结果后，仍留在同一阶段选择戴面具目标；两次可以选同一人或自己。
5. 普通玩家和房主都不应看到舞池名单、面具目标或其他单角色的行动进度；狼队只看到狼队点刀进度。
6. 舞者选择自己入池时，让狼人刀另外两名舞池玩家之一，天亮后该玩家应存活。
7. 女巫毒舞者或假面：目标应存活，但毒药必须显示已用完。
8. 普通狼人全部出局后，假面应从下一次狼人阶段开始获得刀权，仍看不到旧狼队友身份和战术标签。

### 问题 2：语音播报在微信里出得来声吗？

**为什么重要**：语音播报是"手机当法官"的核心。移动端（尤其 iOS 和微信）有**自动播放限制**，
必须先有用户手势才能出声。我做了"点开关时解锁一次"的处理，但**只有真机能验证**。

**怎么测**：每个想听语音的人

1. 在大厅里**点一下「▶ 试听金色传说」**（这一步很关键，它同时完成音频解锁）
2. 打开「语音播报」开关
3. 开局后听：天黑时应该念「天黑请闭眼。现在是第 1 天夜晚。」
4. 逐个确认：狼人 → 「狼人请睁眼，请确认今晚的战术，选择要击杀的玩家。」
5. 重点听**阶段之间的衔接**：「狼人请闭眼。守卫请睁眼，请选择今晚要守护的玩家。」

**要记的**：

| 机型 | 有没有声音 | 音量够不够 | 念得清不清楚 |
|---|---|---|---|
| iPhone | | | |
| 安卓（什么牌子） | | | |

**注意**：iPhone 的**静音拨片**拨到静音时，某些浏览器仍然会出音、某些不会 —— 这个必须实测。
另外手机**音量键**别忘了调。

**如果没声音**：先确认试听按钮能不能出声。试听都没声 → 是手机/浏览器的问题，不是代码。

### 问题 3：切微信、息屏之后，连接断不断？

**为什么重要**：这是**整个项目最大的技术不确定性**。手机息屏或切到微信回消息时，
WebSocket 不一定会立刻断（浏览器的协议层心跳是原生实现的，不需要 JS 参与）。
断得慢 → 系统会以为人还"在线"，该冻结的时候不冻结、该移交房主权限的时候不移交。

**怎么测**（每个人做一次，最好两个人配合观察）：

1. 游戏进行中，**切到微信发一条消息**（别关微信，就切后台），等 **30 秒**
2. 切回来 —— 座位和身份还在吗？界面卡住了吗？
3. 再试一次，这次等 **2 分钟**再切回来
4. 再试：**按电源键息屏 1 分钟**，亮屏后看状态
5. 谁切后台超过 1 分钟，**让旁边的人盯着他手机**上的界面变化（会不会显示掉线）

**要记的**：

| 动作 | 切回来还用不用刷新 | 大概多久算"掉线" |
|---|---|---|
| 切微信 30 秒 | | |
| 切微信 2 分钟 | | |
| 息屏 1 分钟 | | |

**顺带测一个**：在微信里**下拉刷新**页面，看座位和身份还在不在（应该会自动重连恢复）。

### 问题 4：警长和警徽能否走完整闭环？

1. 第一天天亮后，让至少 3 人上警，确认候选图标和提交进度全场实时可见。
2. 候选人退水，确认其立刻离开候选名单，也不能再被警下投票。
3. 故意制造首轮平票，确认进入 PK 发言；第二轮再平票，确认页面显示“无警徽”并有语音播报。
4. 再开一场选出警长，确认座位显示警徽、播放“金色传说”，警长能选发言方向且最后发言。
5. 放逐投票时制造“警长 1.5 票对一张普通票”，确认警长一侧胜出，公开票型标明 1.5。
6. 让警长夜死或被放逐，分别测试移交和撕毁；移交后新警长应立即显示警徽并播放音效。
7. 白狼王在竞选、发言和投票阶段各试一次自爆，确认竞选中止、警徽状态正确且当天直接入夜。

## 四、这些是"还没做"，别当 bug 报

| 你会看到 | 原因 |
|---|---|
| 白天投票 **60 秒自动结算**，不会停下来等你发言 | 白天现在是定时器推进的，你要的"全手动 + 随时改票 + 公示"还没做 |
| 投票平票 → 直接没人出局 | 没有 PK 环节 |
| 服务端重启后进行中的房间没了 | 账号和已完成战绩已持久化，但实时房间状态还没有持久化 |

## 五、出问题了怎么报

**遇到问题时，先别刷新页面**（刷新可能把有用的状态冲掉）。

**手机上报错**：链接后面加 `?debug=1`，然后在手机上想办法看控制台（很难），
或者干脆让**用电脑浏览器**的那个人复现 —— 电脑上能开 F12。

```
http://192.168.31.50:5180/?debug=1
```

加了之后可以在控制台用 `window.__werewolf` 看客户端状态。

**服务端报错**：就是你 `npm start` 那个终端。**别关它**，把出错那几行截图发我。

**最有用的一条信息**：

> "第几天的哪个阶段，谁点了什么，然后界面变成了什么样"

比"卡住了"有用一百倍。
