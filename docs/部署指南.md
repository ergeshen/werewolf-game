# 公网部署指南：让 11 个朋友在任何网络下都能玩

> 本文解决一个问题：**朋友不在同一个 WiFi，怎么让他们玩上。**
>
> 结论先行：必须把服务端部署到一台有公网地址的机器上。当前项目只做 H5，
> 不需要准备微信小程序账号或小程序服务器域名。
> 因为这是**实时对战**游戏（WebSocket 长连接），不能像普通网页那样丢到静态托管，
> 必须有一个**一直在跑的进程**。

---

## 一、先做一个决定：三选一

这里有个关键认知：**临时试玩和长期公开运营需要的基础设施不同。**

| | 方案 A：香港/境外服务器 | 方案 B：国内服务器 + 备案 | 方案 C：内网穿透 |
|---|---|---|---|
| **多久能用** | **1～2 天** | **2～4 周**（备案是瓶颈） | **几十分钟** |
| **要域名吗** | 要（也可以先用 IP） | 要（且必须实名满 3 天才能备案） | 不用，工具给临时域名 |
| **要备案吗** | **不用** | **必须**，免费但耗时长 | 不用 |
| **HTTPS** | 免费证书，几分钟配好 | 同左 | 免费版通常自带 |
| **H5 给朋友玩** | ✅ 可以 | ✅ 可以 | ✅ 可以 |
| **适合阶段** | H5 快速上线 | 大陆长期运营 | 临时试玩 |
| **要花多少钱** | 服务器几百元/年 + 域名几十元/年 | 服务器促销几十元/年起 + 域名几十元/年 | 免费版够 12 人用 |
| **电脑要一直开着吗** | 不用（跑在服务器上） | 不用 | **要**（跑在你自己电脑上） |

### H5 项目的建议

```
小范围试玩 ─── 内网穿透，成本最低，但电脑必须一直开着
公开测试   ─── 香港/境外服务器 + HTTPS，最快上线
大陆长期运营 ─ 国内服务器 + 域名 + ICP 备案
```

如果当前只是验证玩法，不必提前购买国内服务器。确认要长期面向大陆用户运营后，再开始备案。
无论选哪种公网方案，账号密码和登录令牌都要求使用 HTTPS/WSS。

> ⚠️ 关于「大陆服务器 + 穿透绕过备案」：阿里云官方明确说明，
> **即使用内网穿透，只要用大陆服务器对外提供 Web 服务也需要 ICP 备案**。这条路走不通。

## 二、方案 A 详细步骤：最快让朋友玩上

### A-1. 买服务器

- **阿里云**或**腾讯云**的「轻量应用服务器」，选**香港**或**新加坡**节点。
- 配置：**1 核 2G** 就非常够用（12 人狼人杀几乎不吃 CPU 和内存）。
- 系统镜像选 **Ubuntu 24.04**（本文命令都基于它）。
- 买完记下：**公网 IP**、**root 密码**（或 SSH 密钥）。

### A-2. 装 Node（版本必须够新！）

> ⚠️ **这一步是最容易翻车的地方。** Ubuntu 自带的 Node 是 18 或 20，
> **版本太低，服务端根本起不来**。必须装 Node 24。

SSH 登录服务器（Windows 上用自带的 PowerShell 就行）：

```bash
ssh root@你的服务器IP
```

然后：

```bash
# 安装 Node 24
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs

# 确认版本（必须 >= v24，或 v22.18+）
node -v
```

如果 `node -v` 显示的还是旧版本，执行 `sudo apt-get remove -y nodejs` 后重来。

### A-3. 把代码传上去

**在你自己的电脑上**（不是服务器）新开一个命令行窗口：

```powershell
cd "C:\Users\erges\Desktop"
scp -r "微信狼人杀" root@你的服务器IP:/root/werewolf
```

> `scp` 是 Windows 自带的。如果提示找不到，用 WinSCP 或 FileZilla 这类图形化工具拖上去也一样。
>
> **不要传 `node_modules` 文件夹**（几百 MB，多数是给 Windows 用的，服务器上要重装）。
> 如果传得慢，可以先删掉 `node_modules` 再传，然后在服务器上 `npm install`。

### A-4. 在服务器上装依赖并试跑

```bash
cd /root/werewolf
npm install

# 先手动跑一次，确认能起来
node scripts/run.mjs src/server/index.ts
```

看到这个就说明成功了：

```
  12 人狼人杀 · 服务端已启动
  本机访问    http://localhost:5180
```

按 `Ctrl + C` 停掉，进入下一步（要让它后台常驻）。

### A-5. 让它后台常驻 + 开机自启

**必须做这一步**，否则你 SSH 一断开，服务就停了。

```bash
sudo tee /etc/systemd/system/werewolf.service > /dev/null <<'EOF'
[Unit]
Description=Werewolf Game Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/werewolf
ExecStart=/usr/bin/node scripts/run.mjs src/server/index.ts
Restart=always
RestartSec=3
Environment=WEREWOLF_PORT=5180
Environment=WEREWOLF_HOST=127.0.0.1

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now werewolf

# 查看状态（应为 active (running)）
sudo systemctl status werewolf --no-pager
```

`Restart=always` 保证崩溃后自动重启，`enable` 保证开机自启。

> 注意 `WEREWOLF_HOST=127.0.0.1`：这样只允许本机访问 5180，
> 外部必须通过下面的反向代理进来 —— 更安全，也避免绕过 HTTPS。

**常用管理命令：**

```bash
sudo systemctl restart werewolf   # 重启
sudo systemctl stop werewolf      # 停止
sudo journalctl -u werewolf -f    # 实时看日志
```

### A-6. 域名解析

在买域名的地方（阿里云/腾讯云/Namecheap…）添加一条解析记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `game`（或 `@` 表示主域名） | 你的服务器公网 IP |

等几分钟，用 `ping game.你的域名.com` 确认已经指向你的服务器 IP。

### A-7. 配 HTTPS（用 Caddy，强烈推荐）

**为什么用 Caddy 而不是 Nginx**：Caddy 会自动申请和续期 HTTPS 证书，
而且**反向代理 WebSocket 默认就是通的**，不需要任何额外配置。

而 Nginx 如果漏配了转发 Upgrade 头的三行，会出现一个非常折磨人的现象：
**网页能正常打开，但玩家一进房间就连不上，而且没有任何报错**。

Caddy 的配置只有三行：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

然后写配置（把 `game.你的域名.com` 换成你的真实域名）：

```bash
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
game.你的域名.com {
    reverse_proxy 127.0.0.1:5180
}
EOF

sudo systemctl reload caddy
```

**这就完事了。** Caddy 会自动去申请证书（几十秒），并自动处理 HTTPS 和 WebSocket。

### A-8. 放行端口

在云服务商的**安全组 / 防火墙**里放行 **80** 和 **443**。
（80 是 Caddy 申请证书用的，443 是实际访问用的。5180 **不要**对外开放。）

### A-9. 验证部署（重要）

**在你自己的电脑上**执行（项目目录里）：

```powershell
npm run doctor -- --url https://game.你的域名.com
```

它会做三件事：检查接口是否响应、**真正发起一次 WebSocket 握手**、检查是不是 HTTPS。

全部通过会显示：

```
  ✔ /api/health 正常响应
  ✔ 握手成功，并收到服务端消息（收到 welcome 消息）
  ✔ 用的是 HTTPS —— 账号密码和登录令牌需要加密传输
  ✔ 部署没问题，可以把链接发给朋友了
```

**只要没全绿就不要发给朋友** —— 否则他们点进来只会看到一个转圈的页面。

### A-10. 发给朋友

把 `https://game.你的域名.com` 发给玩家。每个人注册/登录后，可以从公开大厅加入等待中的房间。
新账号初始密码为 `1`，首次进入大厅前必须修改。

**顺便让朋友添加到手机主屏幕**：

- **iPhone**：用 Safari 打开 → 底部「分享」→「添加到主屏幕上」
- **安卓**：用 Chrome 打开 → 右上角菜单 →「添加到主屏幕」/「安装应用」

装完是一个图标，点开全屏、没有地址栏。图标和主题色都已经配好了（`web/manifest.webmanifest`），
**HTTPS 一配好就自动生效，不需要额外设置**。

> 一定要用 Safari / Chrome 添加；部分应用内置浏览器没有「添加到主屏幕」菜单。

## 三、方案 B：国内服务器 + 备案

步骤和方案 A 完全一样，只有三处不同：

1. **买国内节点**（阿里云/腾讯云大陆地域），系统还是 Ubuntu 24.04。
2. **先提交 ICP 备案**，再配 HTTPS：
   - 硬性条件：**域名实名认证满 3 个自然日**、**账号实名信息与备案主体一致**、**必须用大陆服务器**。
   - 流程：平台初审 1-2 工作日 → 工信部短信核验（12381，24 小时内完成）→ 管局审核 1-20 工作日。
   - 全程约 **2-4 周**。
3. **备案通过前，80 端口会被云厂商拦截**（这是有意的合规要求，不是你配错了）。
   - 想在这期间先测：把 Caddy 配置改成监听别的端口，比如 `game.你的域名.com:8443`，
     访问 `https://game.你的域名.com:8443`。非标准端口不受备案拦截影响。
   - 备案通过后再改回 443。

## 四、方案 C：内网穿透（不买服务器，几十分钟能用）

原理：在你电脑上跑一个工具，它主动连到一个公网中转服务器，
把公网地址的请求转发到你本机的 5180。

**优点**：免费、立刻能用、**是出站连接所以不受你本机防火墙影响**。
**缺点**：你电脑必须一直开着；免费版地址可能变；部分免费域名可能被浏览器或网络运营商拦截。

常见工具：**cpolar**、**natapp**、**花生壳**、或自建 **frp**（需要自己有台公网服务器）。

以 cpolar 为例（具体以官网当前文档为准）：

```powershell
# 在项目目录里先启动游戏服务
npm start

# 另开一个窗口，启动穿透，把 5180 暴露出去
cpolar http 5180
```

它会打印一个公网地址（形如 `https://xxxx.cpolar.cn`），把这个发给朋友。

> ⚠️ 免费版地址通常 **24 小时内会变**，临时调试可以，不适合发给 12 个人长期用。
> 长期用请升级套餐或直接买服务器（方案 A）。

## 五、部署后可能遇到的坑

### 坑 1：页面能打开，但进房间就连不上 ⭐ 最常见的失败

**原因**：反向代理没转发 WebSocket 的 `Upgrade` 头。
**判断**：`npm run doctor -- --url https://你的域名` 会直接告诉你。
**解决**：用 Caddy（默认就对），或者给 Nginx 补上这三行：

```nginx
location /ws {
    proxy_pass http://127.0.0.1:5180;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    # WebSocket 是长连接，超时时间必须放大，否则空闲一会儿就被掐断
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}

location / {
    proxy_pass http://127.0.0.1:5180;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

### 坑 2：`node -v` 显示 18 或 20，服务起不来

**原因**：Ubuntu 自带 Node 版本太旧，不支持直接运行 TypeScript。
**现象**：报一堆看不懂的语法错误。
**解决**：按 A-2 装 Node 24。
（本项目已经加了版本守卫，会直接提示「Node 版本太低」并给出升级命令，不会再让你看天书。）

### 坑 3：千万别开多进程 / 负载均衡 ⭐ 会静默地把游戏搞坏

**房间数据全部存在这一个进程的内存里。**
如果你用 `pm2 start -i max` 开多实例，或者配了负载均衡，
**同一个房间的玩家会被分配到不同进程，彼此看不见对方** —— 表现为「进去就卡住」。

**必须保证只有一个进程实例。** systemd 的写法（本文 A-5）天然就是单进程，最安全。

### 坑 4：服务器重启后服务没了

`systemctl enable` 没执行。补上：

```bash
sudo systemctl enable werewolf
```

### 坑 5：手机浏览器打开是空白 / 一直转圈

按顺序排查：

1. 换一个标准浏览器（Safari / Chrome）打开；仍然不能开通常是部署或网络问题。
2. 跑 `npm run doctor -- --url https://你的域名` 看是哪一层不通。
3. 有些免费穿透域名会被浏览器或网络运营商拦截 —— 换 Caddy + 自己的域名试。
4. 确认是 HTTPS 而不是 HTTP。

## 六、以后怎么更新代码

在你电脑上改完代码后：

```powershell
# 从电脑推到服务器
scp -r "C:\Users\erges\Desktop\微信狼人杀\src" root@你的服务器IP:/root/werewolf/
scp -r "C:\Users\erges\Desktop\微信狼人杀\web" root@你的服务器IP:/root/werewolf/
scp "C:\Users\erges\Desktop\微信狼人杀\package.json" root@你的服务器IP:/root/werewolf/
```

然后在服务器上重启：

```bash
cd /root/werewolf
npm install --omit=dev   # 如果依赖有变化才需要
sudo systemctl restart werewolf
```

> 前端是「零构建」的：改完 `web/` 里的文件直接生效，**服务器上不需要任何打包步骤**。
> 这也是本项目的设计选择之一 —— 部署只要 `npm start`。

## 八、数据备份

账号和已完成战绩默认保存在项目目录的 `data/werewolf.db`。更新代码时不要覆盖或删除
`data/`。SQLite 使用 WAL 模式；备份前先停止服务，再复制整个 `data/` 目录，避免漏掉
尚在 `-wal` 文件里的事务。正在进行的房间不在数据库里，重启服务前应先结束当前对局。

如需把数据库放到独立数据盘，在 systemd 服务里设置：

```ini
Environment=WEREWOLF_DB_PATH=/var/lib/werewolf/werewolf.db
```

并提前创建目录、把写权限授予运行 Node 服务的系统用户。
